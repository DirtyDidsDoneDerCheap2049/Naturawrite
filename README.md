# Naturawrite · 自然风格写作

[English](README.en.md)

**Naturawrite 是一个减少 AI 味的写作技能。** 它修正语病，删去无用的铺垫、重复和夸张评价，理清句子之间的关系，让文章更容易一遍读懂。

名字由 **natural + write** 合成，表示自然风格写作。

## 修改示例

**原稿**

> 现在支持多人编辑同一份文档。每个人的修改都会实时显示。这不仅是一次功能升级，更是协作方式的深层重构。更重要的是，评论会跟随所引用的句子移动。值得注意的是，这个功能对所有用户免费。

**修改后**

> 现在，多人可以同时编辑同一份文档，各自的修改都会实时显示，评论也会随引用的句子移动。这项功能对所有用户免费。

修改保留了原稿的功能信息，删去“深层重构”等没有依据的评价和不必要的提示语，并把相连的意思组织在同一句中。更多示例见 [examples.md](examples.md)。

## 适用范围

- 审校或改写中文、英文的文章、报告、邮件、产品说明和技术文档。
- 按指定读者、用途和体裁写新稿。
- 参考作者的写作样本，调整用词、句法和节奏。

改稿会保留原有的体裁、语气、事实和必要的专业术语，正式稿件也可以保持正式。降低 AI 味靠的是编辑文字，不需要添加虚构经历、强行口语化或故意写错。技能不用于判断文本是否由 AI 生成，也不保证通过 AI 检测。

## 安装

### 本地安装

在仓库目录中运行：

```sh
npx skills add . --global --agent codex --skill naturawrite
```

安装到其他工具时，将 `codex` 换成 Skills CLI 支持的 agent 名称，例如 `claude-code` 或 `opencode`。去掉 `--global`，即可安装到当前项目。

### GitHub 安装

在终端运行：

```sh
npx skills add DirtyDidsDoneDerCheap2049/naturawrite --global --agent codex --skill naturawrite
```

也可以下载仓库，将整个目录复制到所用工具的技能目录，命名为 `naturawrite`。在 Codex 中，对应路径是 `~/.codex/skills/naturawrite/`。其他安装选项见 [Skills CLI](https://github.com/vercel-labs/skills)。

### Claude Code 插件

仓库包含 Claude Code 所需的插件和 marketplace 配置。在本地仓库目录中运行：

```text
/plugin marketplace add .
/plugin install naturawrite@naturawrite
```

## 使用

在 Codex 中，用 `$naturawrite` 指定这个技能：

```text
使用 $naturawrite 审校下面这段文章。保留技术术语和事实，直接给出改好的正文：
[待修改文字]
```

修改文件时，注明路径和需要编辑的范围：

```text
使用 $naturawrite 修改 docs/report.md 的正文，保留原有体裁和技术含义。
```

技能默认返回改好的正文。需要逐句对照或修改理由时，在请求中注明；修改文件时，只编辑指定范围内的正文，保留代码、命令、结构化数据、路径和链接目标。Claude Code 插件的调用命令是 `/naturawrite:naturawrite`。

写新稿时，提供读者、用途和已有事实，也可以附上一两段自己的文字作为文风参考。样本中的个人经历只有在你明确要求写入时，才会用于新稿。

## 26 项编辑检查

下表概括了 26 条编辑规则，完整说明见 [SKILL.md](SKILL.md)。

| # | 检查项 | 编辑要点 |
|---|---|---|
| 1 | 搭配和句式杂糅 | 修正搭配、修饰关系和混用的句式 |
| 2 | 主语与动作 | 说明谁做什么，避免主语漂移 |
| 3 | 并列层级与凑数三项 | 并列项同级，内容互不重复 |
| 4 | 没有对象的对比 | 对比的对象在语境中真实存在 |
| 5 | 反驳不存在的观点 | 不凭空制造反方来衬托结论 |
| 6 | 假转折与假深刻 | 转折表达实际变化，概念帮助解释内容 |
| 7 | 宣告式开场 | 从内容开始，删除无用的开场宣告 |
| 8 | 重复、长度包装与标题复述 | 删除重复信息，不靠篇幅制造完整感 |
| 9 | 标点承担的关系 | 用标点表达实际的句法和逻辑关系 |
| 10 | 限定语叠加 | 不确定性只留在影响判断的地方 |
| 11 | 读者不懂的术语和空概念 | 按读者选择词汇，说明必要术语的含义 |
| 12 | 只有气氛相似的比喻 | 比喻两边有具体的机制、关系或因果对应 |
| 13 | 意义和效果被夸大 | 按事实和比较条件描述意义与效果 |
| 14 | 模糊的关系 | 写出材料提供的动作或关系 |
| 15 | 句尾附加的空洞判断 | 删去没有依据或实际内容的附加评价 |
| 16 | 广告语和无依据赞美 | 评价有具体特点或证据支持 |
| 17 | 借来的权威与结论层级 | 引用真实来源，区分事实、推测与已证实结论 |
| 18 | 知识缺口、假精确与猜测 | 表达精度不超过证据精度 |
| 19 | 装饰性格式 | 让格式便于查找、比较和执行 |
| 20 | 聊天和草稿残留 | 删去成稿中的闲聊套话和草稿提示 |
| 21 | 词汇复杂度与句法复杂度匹配 | 用有层次的复句表达复杂关系，避免连续的抽象短句 |
| 22 | 防御性解释与无用的自我保护 | 直接给出主张与理由，保留影响结论的条件 |
| 23 | 思路推进优先于格式模板 | 按思路组织段落，不强行套用模板 |
| 24 | 省略主语时保持动作主体一致 | 动作主体变化时，写出新的主语 |
| 25 | 标题只说明内容 | 标题说明本节内容，删去教师式设问与写法提示 |
| 26 | 成稿不展示无用的证据权衡和判断过程 | 给出结论、事实与必要限制，删去无用的判断过程 |

## 致谢

本技能的部分规则来自于 [Humanizer](https://github.com/blader/humanizer)，包括上文第 2–10、13–17、19–20 条，并对这些规则进行了筛选与改造和重写，本skill的诞生原因部分就来自于使用该skill过程中感受到的问题与缺陷。

筛选过程参考了 [AI Manuscript Repair](https://github.com/eglantine-shell/ai-repair) 的启发：先按普通编辑标准修复语病和不通顺的表达，不通过刻意模仿人类习惯来降低 AI 味，避免变成AI对人类的cosplay，让人类产生厌恶感。该项目提供了编辑思路，本技能没有复制它的代码、提示词或规则文本。

其余原则来自作者与 GPT 5.6 讨论过程中形成的原创规则，包括词汇是否适合读者、比喻是否存在关系对应、表达精度是否超过证据精度、事实与机制推测的区分，以及中文词汇与句法复杂度的匹配、防御性解释、按思路推进、省略主语时保持主体一致、标题只说明内容、不展示无用的判断过程。这些原则也补充和改造了部分保留的 Humanizer 规则。
